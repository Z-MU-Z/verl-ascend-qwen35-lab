## Network / Package Download Findings

This point matters a lot for the next agent.

Observed on `.36`:

- direct `pip` downloads from the configured public mirror can time out even when the version is valid
- this affected at least:
  - `torch-2.9.0` (`104 MB`)
  - `numpy-1.26.4` (`14 MB`)
- the common failure shape was:
  - `pip._vendor.urllib3.exceptions.ReadTimeoutError`

Configured mirror during this work:

- `https://pypi.tuna.tsinghua.edu.cn/simple`

Interpretation:

- the issue was not "wrong version"
- the issue was not "wrong index"
- the issue was remote download reliability from `.36`

Reliable workaround already proven:

1. download wheels locally on the Mac side
2. upload them to `.36` under `/home/zmz/bootstrap_bundle/python/`
3. install on `.36` with:

```bash
python -m pip install --no-index --find-links=/home/zmz/bootstrap_bundle/python ...
```

For the next `.36` agent, the most important implication is:

- prefer reusing staged local files under `bootstrap_bundle/`
- avoid blind repeated remote downloads of medium or large wheels
